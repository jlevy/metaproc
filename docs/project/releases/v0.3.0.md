# Metaproc v0.3.0

Metaproc now records what each task attempt actually did, as a durable fact written
before the work starts and finalized once when it ends.
Replay reads that history instead of inferring it, and a crashed process reconciles
against it on restart.
Around that, this release adds item-aligned chains and fan-in to process specs, gives
agent steps their validation failures back as retry feedback, and hardens GCP Batch
dispatch.

## What’s Changed

### Features

- **Durable per-attempt task history:** Work managed by `run-process`, `run-parallel`,
  or a waited `run-step` writes a typed `metaproc:TaskAttemptRecord/0.1` before
  execution and finalizes it once with its disposition and failure class.
  Replay consumes that exact history when present, and startup reconciliation closes
  attempts orphaned by a crash and rebuilds a missing terminal projection without
  disturbing work owned by a live step-scoped pool.
  Attempt success waits for every attempt-owned validator, including the fan-out
  write-boundary check, and a resume refuses status or history addressed to another run,
  step, or item.
- **Item-aligned chains, fan-in, and declared retry:** Process specs can chain steps
  against the same fan-out item, collect fan-out results into a typed fan-in outcome,
  and declare retry policy in the spec.
  A resume enters a chain even when its head is already complete, rerunning incomplete
  tasks and reusing completed ones.
- **Retries that say what was wrong:** An agent step that produced invalid output gets
  the structured validation failures appended to its next prompt — output, failure kind,
  path, contract, invariant, location, and message — instead of being asked again with
  no new information. Transport failures never create or replace that feedback.
- **Schema conform for agent-authored YAML:** A frontmatter scalar that YAML would
  resolve to the wrong type is requoted against the contract about to judge it, so a
  value genuinely named `1850` survives a `type: string` field.
  Only pydantic `string_type` errors are acted on and the document’s own serializer
  rewrites it, so `1.10`, `007`, `1e3`, and `0x1F` keep their written form.
  A real type disagreement still fails.
- **Host admission for single-step runs:** A `run-process` invocation with no `for_each`
  is admitted through the same host gate as fan-out work, so several orchestrators on
  one machine account for each other instead of launching blind.
  Admission is best-effort by design: an unreachable gate or a wait timeout lets the
  launch proceed rather than failing a step that worked before admission existed.
- **GCP Batch dispatch:** `metaproc gcp run` accepts repeatable
  `--workspace-package PATH` to install current-branch consumer packages, prints Batch
  state transitions while provisioning and executing, and emits an exact resource
  identity that `gcp status`, `gcp logs`, and `gcp cancel` reattach to.
  Default workspace archives exclude top-level and vendored Metaproc source layouts, and
  safe in-repository symlinks are materialized as archive content while external links
  and directory-link cycles are rejected.

### Fixes

- **Retry classification no longer depends on a filename:** Whether to retry a missing
  output or give up on a structural mismatch was recovered by substring-matching a
  rendered error sentence that contained the artifact’s name, so two outputs missing for
  the same transient reason could get opposite verdicts because one was named for a
  schema manifest. The decision now reads the structured failure kind.
- **Representation-only validation failures:** `date`, `datetime`, `time`, `Decimal`,
  and `UUID` values normalize to their serialized form before the structural pass, so a
  quoted and an unquoted YAML date stop disagreeing.
  Only types with an unambiguous serialized form convert.
- **Cloud log tailing:** Cloud Logging datetimes are normalized to RFC3339 before use as
  tail watermarks, fixing a tail that could fail mid-run, and a blocking generic run
  reuses and closes one logging client instead of leaking one per poll.
- **Wheel overrides preserve the image dependency closure:** A verified Metaproc wheel
  override installs with `--no-deps`, keeping the image’s audited dependencies and
  per-package release-cutoff exceptions, and nested `uv` commands stay on the baked
  environment after package installation.

### Compatibility

- **Code-step outputs are no longer YAML-repaired.** `run-parallel`’s `mode: code`
  fan-out ran the frontmatter auto-repair pass over each item’s declared outputs before
  validating them; `run-process`’s code path never did.
  Both now leave the document alone.
  A process whose code handler relied on that repair will start reporting
  `invalid_outputs` — fix the handler’s serializer rather than the artifact.
  Repair and conform stay scoped to agent-authored output.
- **A Gemini CLI below the supported minimum is now refused, not warned about.** The
  adapter passes `--skip-trust`, introduced in gemini-cli 0.40, so an older CLI failed
  every agent step partway through a run with an unexplained “Unknown arguments”.
  The refusal reports the version found, the path it resolved, and the remedy.
  Drift at or above the minimum stays a warning.
  If a stale CLI is shadowing the pinned binary on `PATH`, runs that previously started
  and then failed will now stop immediately.
- **`cryptography` moves to 50.0.0**, retiring the audited advisory waiver for
  `GHSA-g6cj-pr64-35w5` / `CVE-2026-69247`. No advisory waiver is active in this
  release.
- **Replay parity has one known gap.** A task blocked purely on credential-pool capacity
  is recorded as running with a persisted attempt before admission is granted, and
  replay counts those lost records against `max_attempts`. A run that merely waited on
  capacity several times can therefore replay as failed while production considered it
  healthy. Live execution is unaffected — the pool-exhausted path does not consume the
  production retry budget — so this is a post-hoc analysis limitation, not a run-outcome
  one. Tracked as `mp-ux0f` and `mp-f5m5`.
- **Legacy run trees remain readable.** Readers fall back to status-based compatibility
  when durable task facts are absent.
  The full mixed-authority boundary is still being proven out under `mp-g315`; if you
  depend on reading pre-0.3.0 run trees, verify against your own corpus.
