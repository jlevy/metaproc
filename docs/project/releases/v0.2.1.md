# Metaproc v0.2.1

## What’s Changed

### Features

- **Operational resource reporting:** Runtime and agent evidence now feeds one
  deterministic resource ledger.
  CLI and Metabrowser views distinguish measured, estimated, and unmeasured values;
  report provider meters and coverage gaps; evaluate reporting-only budgets; and recover
  missing reports for inactive runs without calling provider APIs.
- **Code-step telemetry:** `run-process`, `run-step`, and `run-parallel` sample CPU and
  memory for handlers and child processes.
  Step lifecycle events add wall time to the owning resource nodes, including nested and
  fan-out execution.
- **Typed identities:** New runs use compact, time-ordered `run-...` identities.
  GCP Batch jobs retain a readable label and a collision-resistant exact identity key,
  so status, logs, cancellation, and inventory keep distinct runs separate.
- **Version discovery:** `metaproc --version` prints the installed distribution version.

### Fixes

- **Resource correctness:** Terminal recovery preserves successful outcomes, historical
  reports regenerate their complete artifact set, and current resource documents use a
  registered SoftSchema contract while strict V1 and V2 readers remain available.
- **Latency attribution:** Paired Claude and Gemini tool spans now carry measured
  duration. Missing or invalid timestamps stay unmeasured, and reversed timestamps do not
  produce negative latency.
- **Cloud source preflight:** Consumer repositories with Metaproc in a submodule or
  vendored path are detected before cloud dispatch, preventing branch changes from
  silently falling back to image-baked code.
- **Cloud artifact guidance:** Wheel and workspace URIs are documented with their
  required SHA-256 digests, and the architecture now matches the verified `/opt/venv`
  installation and workspace-extraction paths.

### Guidelines and Content

- **Portable Agent Skill:** The generated `.agents` and `.claude` skill copies use
  portable tool language, stay byte-for-byte aligned with the packaged skill, and route
  operators to the packaged manuals.
- **Documentation structure:** The README and developer guide now provide
  audience-oriented navigation, architecture and file-I/O references match the public
  implementation, and completed project plans live under `docs/project/specs/done/`.

### Compatibility

- New default run IDs no longer embed process and title slugs.
  Set `RUN_ID_TEMPLATE` explicitly when an integration still requires the historical
  format. Existing underscore-form IDs and fully legacy GCP jobs remain readable.
- New `resources.json` files use `metaproc:ResourcesDocument/0.1`. Metaproc continues to
  read strict `metaproc.resources/v1` and `metaproc.resources/v2` files.
- SoftSchema is now constrained to `>=0.6.0,<0.7`. Integrations that call SoftSchema
  directly must use its document terminology and 0.6 API.
- Resource budgets remain observational.
  They report outcomes but do not block dispatch, change scheduling, or terminate a run.
