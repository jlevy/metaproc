# Metaproc v0.4.1

A patch release about being told the truth by your own run.

Two kinds of evidence were being thrown away.
A step that named a model it wanted could be answered by a different one, because an
unrecognized name warned and ran the adapter’s default instead.
And a run pool that emitted its controller ceilings, health samples, and quota pauses
had a typed reader that dropped them, so the record on disk was richer than anything a
consumer could read back.

Both are fixed here, along with cleanup and admission accounting that could be skipped
when bookkeeping failed.
No public CLI surface, process-file field, plugin entry point, or adapter default
changed, and no previously accepted model identifier was removed.

One behavior change needs a look before upgrading: an unknown model name is now an error
rather than a silent substitution.
See Compatibility.

## What’s Changed

### Fixes

- **An explicit model selection is preserved, or refused — never quietly replaced.** In
  v0.4.0 every adapter validated the configured model against its own allowlist and, on
  a miss, logged a warning and passed its default instead.
  A step pinned to a model ran on a different one, and the run’s cost, latency, and
  quality were attributed to a name that never served it.
  A warning in a log is not a signal an unattended fan-out reads.
  All four adapters — `claude-code-cli`, `codex-cli`, `gemini-cli`, and `pi-cli` — now
  route selection through one reviewed catalog.
  An omitted selection still takes the adapter default; an explicit one is either passed
  through exactly as written or rejected with an error naming the adapter and the
  identifier. The default is never substituted for something a spec actually asked for.
  `metaproc auth check` reports such a rejection as a failed check line rather than
  aborting the probe, and its `--assert-model` help no longer describes a
  warn-and-default path that no longer exists.

- **RunPool controller, health, and quota evidence survives the typed reader.** The pool
  event log already recorded the concurrency controller’s memory, provider, and operator
  ceilings, its effective target and current bottleneck, active RSS and log-byte totals,
  periodic `health_sample` records, and the `quota_pause_started` / `quota_pause_tick` /
  `quota_pause_resumed` sequence.
  The typed event models carried none of it: the extra fields were narrowed away on
  read, and the health and quota-pause records had no model at all.
  A consumer reading the typed stream saw a thinner run than the one on disk, and could
  not tell a pool waiting on a provider quota from a pool that had simply gone quiet.
  The models now retain every field the logger emits, and the three quota-pause records
  and `health_sample` parse as themselves.

- **Cleanup and admission accounting survive a bookkeeping failure.** Three ways a
  failure could compound itself are closed.
  An exception while recording a started child no longer skips the cleanup obligations
  that a poll failure already honored, so admission stays held until the child is reaped
  rather than being released under a process still running.
  A failure writing the `host_slot_acquired` event now releases the lease the caller
  never received, instead of leaking a slot for the rest of the run.
  And when shutdown fails while the pool is already unwinding a caller’s exception, the
  original error is raised with the shutdown failure attached as a note rather than
  being replaced by it — the second error is the one you can see, and the first is the
  one that explains the run.
  Quota-pause timers are cancelled and drained during shutdown, and the event and health
  loggers are closed even if the shutdown record fails to write.

### Added

- **A reviewed model catalog with dated evidence.** `metaproc.config.model_catalog`
  centralizes accepted identifiers, per-adapter defaults, the source URLs each entry was
  reviewed against, a review date and interval, and lifecycle notes recording retirement
  dates and account-dependent routes.
  Nothing was removed from any adapter’s accepted set and all four defaults are
  unchanged (`opus`, `gpt-5.5`, `gemini-3.1-pro-preview-customtools`, and `sonnet`).
  Newly accepted:
  - `claude-code-cli` gains `claude-fable-5-1`, `claude-fable-5`, `claude-opus-5`,
    `claude-sonnet-5`, `claude-opus-4-8`, and the `fable` alias.
  - `codex-cli` gains `gpt-6-astra`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`,
    `gpt-5.6`, and `gpt-5.3-codex-spark`.
  - `gemini-cli` gains `gemini-3.5-flash-lite`.
  - `pi-cli` gains `claude-opus-5`, `claude-sonnet-5`, `claude-fable-5`,
    `claude-opus-4-8`, `gpt-6-astra`, the three GPT-5.6 variants, and Gemini 3.8, 3.7,
    3.6 Flash and 3.5 Flash-Lite.

  `claude-fable-5-1` is accepted by `claude-code-cli` only: it is absent from the pinned
  Pi 0.84.2 native catalog, and Claude Code needs a newer client than this release’s
  2.1.234 pin. Acceptance means Metaproc preserves an identifier, not that an account,
  client, or API can serve it.

- **Pi model acceptance derives from the packaged provider catalog.** `pi-cli` accepted
  identifiers now come from `pi-models.default.json` itself, plus a small retained set
  of native selections, so adding a provider entry no longer requires a second,
  separately maintained allowlist edit that could silently disagree with it.
  Vertex MaaS entries resolve under both their publisher-qualified and short IDs, as
  Pi’s own lookup does.

- **Four more Codex reasoning-effort values.** `none`, `xhigh`, `max`, and `ultra` are
  the remaining named values in the pinned codex-cli 0.147.0 parser and are now accepted
  alongside `minimal`, `low`, `medium`, and `high`. Accepting the syntax does not mean
  every model supports every effort.

- **Pressure checks carry their hold hysteresis.** Every `pressure_check` record now
  includes `consecutive_normal` and `consecutive_elevated`, so a reader can tell how
  close the controller is to changing its mind rather than inferring it from a run of
  samples. See Compatibility.

- **Refreshed provider data.** `pi-models.default.json` adds the Gemini Vertex 3.8, 3.7,
  3.6 Flash and 3.5 Flash-Lite entries and the GPT-6 Astra and GPT-5.6 Sol, Terra, and
  Luna entries, the latter using the per-model `openai-responses` override the pinned Pi
  client supports; existing entries keep the provider’s Chat Completions default.
  Vertex Gemini entries that accept image input are marked as such, and the
  `gemini-3.1-pro-preview` context window is corrected to 1,048,576 tokens.
  Entries whose exact identity this review could not establish in primary documentation
  — the Moonshot Kimi ID among them — say so where a reader will find it rather than
  implying a verification that did not happen.
  `pricing.md` is refreshed against the same sources.

### Guidelines and content

- **The Agent Skill’s debugging guidance is reversed where it was wrong.** v0.4.0’s
  skill told an agent never to inspect a run with ad hoc shell commands over the run
  directory, `.state/`, or `.logs/`, and to treat any such need as a missing Metaproc
  command. That is right for run state and lifecycle and wrong for debugging: some
  captures merge stdout and stderr or filter native events, so a Metaproc rollup or an
  extracted trace can omit evidence that only the captured log holds.
  The skill now keeps the strong rule for state and lifecycle — use `status`, `wait`,
  `tail`, `pool`, `trace`, `stats`, `auth usage`, `gcp`, and do not wrap them in a
  private orchestrator — while directing an agent to read the relevant attempt’s
  captured output and native transcript directly when diagnosing a failure, to report
  the cause with its evidence location, and to say what is missing when the logs do not
  contain it. Filing a missing diagnostic as an issue is now something you do while
  continuing the investigation, not instead of it.
  The committed `.agents/` and `.claude/` skill copies are regenerated to match.

### Documentation

All shipped documents are `metaproc help` topics, so these change the installed package.

- **A new operator section for each question the framework kept answering privately.**
  `metaproc help operator` gains **Direct Agent Debugging** (which captured paths hold
  what, and when a rollup is not enough); **Two Concurrent Runs on One Host** (they
  share a disk-backed slot gate, each brings its own limit, admission fails open, and
  `METAPROC_HOST_MAX_LOCAL_AGENTS` composes by minimum, so it can only lower a cap,
  never raise one); **Reading Pool Health** (available memory is the budget, swap growth
  is the degradation signal, `elevated` with work pending is back-pressure working as
  intended, and the swap term lags on macOS because the compressor goes unread); **The
  Subprocess Count Is a Display Estimate**, which is not the number the governor acts
  on; and **A Green Run Is Not a Reviewed Run**, since `status --check completed` passes
  on a run that produced nothing.

- **The cause-preservation invariant is stated where it binds.** `metaproc help design`
  gains §13 “Cause Preservation at Aggregation Boundaries”: no aggregation boundary may
  discard a cause it received.
  A step summarizing items, a run summarizing steps, a serializer omitting a field, and
  a typed reader ignoring an undeclared key are all aggregation boundaries, each free to
  summarize but not to summarize a cause down to nothing.
  Three current gaps are named so they are not rediscovered as novel: the untyped step
  entry in `process-status.yaml` that records `state: failed` with no `error` for every
  step that is not a scalar code step; admission, which logs a slot taken but never one
  waited for or denied; and the runpool reader gap this release closes.

- **The fan-in manifest’s emitted field set is documented.** §11 described four per-item
  fields; the projection of each `OutputFailure` actually carries at most `output`,
  `kind`, `contract`, `invariant`, and `location`, omits any field whose value is
  absent, and drops the artifact path and rendered message the per-item record keeps.
  A consumer assuming a path or message was reading empty records with nothing in them
  to say why.

- The runpool and execution documents are aligned with the admission, pressure, retry,
  artifact, and cause-preservation contracts as they actually behave, and the
  scalar-admission module’s own description now matches where that gate sits: agent
  leaves acquire it before submitting to the run-owned pool, and mapped leaves reach the
  same path, so a “scalar” execution function never implied a scalar-only scope.

- Repository gate: the shipped-document freshness check compares Git author timestamps
  in UTC. A commit authored west of UTC late in the day was read as the next day’s
  change and failed a document whose header was correct, which is what happened to CI on
  the model-catalog commit in this release.
  The UTC header convention is now written down alongside the check.

## Compatibility

- **An unknown model name now fails the step instead of running the default.** This is
  the intended fix, and it is the one change that can turn a v0.4.0 run that appeared to
  work into a v0.4.1 run that stops.
  If a process spec, execution profile, or adapter map names an identifier Metaproc does
  not recognize, that step now raises `unknown <adapter> model <name>` at command
  construction instead of silently running the adapter default.
  Such a run was already not doing what its spec said; the failure is the disclosure.
  Before upgrading, check any pinned model names against the accepted sets above, and
  extend `metaproc.config.model_catalog` if you need an identifier it does not yet
  carry. An empty-string model is treated as an explicit selection and rejected on the
  same grounds; omit the field to take the default.

- **`pressure_check` records gain two fields.** `consecutive_normal` and
  `consecutive_elevated` are new keys in the pool event stream.
  Readers that tolerate unknown keys are unaffected; a consumer validating these records
  against a closed schema of its own needs to admit them.

- **Nothing was removed.** No adapter default changed, no previously accepted model
  identifier was dropped, and no CLI flag, process-file field, runtime artifact, or
  plugin entry point was removed or renamed in this release.
  Stored runs and existing specs that named recognized models keep working unchanged.

- **Still open from v0.4.0:** Gemini steps ship with
  `context.fileFiltering.respectGitIgnore: False`, so a Gemini step’s own file tools can
  read ignored files anywhere in the workspace, `.env` included.
  This is unchanged in v0.4.1 and is disclosed in the amended v0.4.0 notes and in
  `metaproc help design`. Whether the default itself should become opt-in is still open
  as `mp-x1qh`. Treat a workspace a Gemini step runs in as readable by that step.
