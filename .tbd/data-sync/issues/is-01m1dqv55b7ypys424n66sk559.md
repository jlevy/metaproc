In the trading workspace at Metaproc source HEAD 72ae119 (git describe v0.3.0-85-g72ae119), uv run --frozen --project vendor/metaproc metaproc --version reports 0.3.1.dev82+1ce0d8f. import inspection proves metaproc is loaded from the correct editable source tree, but importlib.metadata remains stamped at the older commit. This makes the CLI version disagree with the executable source after an ordinary submodule update. Acceptance: define the intended identity contract for editable installs; either refresh metadata automatically through the supported workspace bootstrap or make the CLI expose the source revision separately and identify stale distribution metadata; add a test that advances an editable source checkout without silently claiming the old build identity. Production run identity must continue to use a verified full Metaproc revision.
