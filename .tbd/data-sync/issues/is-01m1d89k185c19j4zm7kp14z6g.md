At Metaproc 72ae119, the GTIA v3 production graph passes check-handlers with 37/37 handlers, but `metaproc check-headers v3-gtia/process/cohort.process.md` reports 20 errors after successfully traversing the graph. The failures fall into three categories: contract templates with placeholder or deliberately incomplete values are validated as concrete artifacts; prompt paths containing `{{run.dir}}` are treated as repository-relative missing files; and non-frontmatter prompt support files are treated as invalid typed documents. Define the static command boundary so authored process and runbook frontmatter is still checked without misclassifying runtime-produced inputs or template scaffolds. Add focused fixtures for all three cases and an integration fixture proving a consumer process tree can pass both check-handlers and check-headers without suppressing a genuinely missing or invalid document.
