The scalar-agent nonzero-exit rescue currently runs for any exit_error, including RunPool kill reasons, although the policy and evidence justify overriding only an unreliable process exit code. Its precheck also validates output templates with the parent variables instead of the step variables that bind the effective execution profile and artifact namespace, and the accepted anomaly survives only as suppressible progress output rather than durable attempt evidence. Restrict the override to nonzero exits without a supervisor kill, validate with the same resolved step variables and repair/conform ordering as normal completion, retain durable anomaly evidence, and add integration tests for rescued exit, pool kill, variant output, invalid output, and outputless cases.

## Notes

## Re-verified still open at main 72ae119, 2026-08-31

Confirmed in `src/metaproc/commands/run_process.py`, all three sub-findings intact:

1. Supervisor kills are rescuable. `exit_error` is set to
   `f"RunPool killed process: {pool_kill_reason}"` when the pool killed the child, and
   the rescue guard is only `if exit_error is not None and effective_outputs and
   artifact_dir is not None:` — it never distinguishes a kill from a nonzero exit. The
   block's own comment justifies the override solely by unreliable adapter exit codes,
   so a RunPool kill being rescued contradicts the stated policy.
2. Wrong variable bindings in the precheck. The rescue calls
   `validate_item_outputs_detailed(artifact_dir, effective_outputs, variables=variables)`,
   while the normal completion path 80 lines below uses `variables=step_vars` in all
   three of its calls. `step_vars` is `dict(variables)` plus `EXECUTION_PROFILE`,
   `ARTIFACT_NAMESPACE`, and `VARIANT`; a comment on the completion path explicitly
   records "step_vars (not variables): only step_vars has VARIANT bound". So for any
   variant-bearing output the rescue validates a different path than the step writes.
   Note `artifact_dir` itself is computed from `step_vars`, so the two halves of the
   check disagree.
3. No durable evidence. The accepted anomaly survives only as `out.progress(...)`,
   which is suppressible; nothing lands in the attempt record.
