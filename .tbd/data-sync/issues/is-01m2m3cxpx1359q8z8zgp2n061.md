src/metaproc/commands/status.py:122 returns from _recover_resource_artifacts whenever resource_artifacts_need_recovery is false, so the operations-summary write at :138 never runs for a run whose resource artifacts are already fresh but whose operations-summary.md is absent. Reachable when a signal arrives between finalize_run_resources and finalize_operations_summary, when the operations fold raises at finalization (caught and logged), or when an earlier status already recovered the resources of a killed run. This narrows P1-R5, the fix meant to give killed runs a summary.

Fix: lift the summary exists() check above the needs_recovery gate, keeping it write-once. State it in the operator reference, which today promises recovery for the killed case only.

Regression test: fresh resource artifacts, no operations-summary.md, status writes one.
