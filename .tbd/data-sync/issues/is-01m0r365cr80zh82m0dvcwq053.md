A non-fan-out agent output can declare `on_invalid: ...: retry`. Metaproc records and prints the typed `OutputFailure`, then repeats the step with the unchanged `resolved_prompt`. The second attempt therefore knows neither which output failed nor which invariant to correct; it is a blind reroll.

This leaves the failure mode that motivated feedback-aware recovery exposed: a producer that repeats the same semantic mistake can consume its one content retry and still lose the item even though the validator has the exact correction signal.

Append a bounded, framework-authored correction section to invalid-output retry prompts using the structured failure summaries. It must apply only to the next content retry, preserve the original prompt verbatim, stay absent from the first attempt and transient transport retries, avoid incorporating arbitrary log prose, and be covered through the real non-fan-out executor. Keep the framework consumer-agnostic.
